# 第三问：正负反馈探测与扫描前瞻

**本轮没有找到足以替换 time/lean 的提速方案，也没有验证整局约2300秒的成绩。** 两个方向已经实现并完成本地配对开发实验。新测点的首轮单场收益没有在扩大条件后稳定延续，扫描前瞻则出现了明显退步。

当前正式入口仍是项目根目录的[运行第三问](../../运行第三问.cmd)。本目录没有官方运行入口，全部实验通过隐藏真值的公开接口在自建环境中进行。本轮没有连接官方模拟器。

## 结果与选择

先运行3个初步条件，随后保持候选源码不变，扩展到4类布局、每类2个独立布局、每布局2个固定空间误差场，共16个条件。两种误差场复用同一个源布局，**不能称为16个独立布局**。这两批均属于开发实验，没有包装为留出集。

扩大开发集的同条件配对结果如下，时间均为整局虚拟秒：

| 方案 | 平均时间 | 相对 lean | 更快／相同／更慢 |
|---|---:|---:|---:|
| 冻结主方案 lean | 3146.04 | — | — |
| 仅增加正负反馈探测 probe | 3144.72 | 仅省1.32秒，0.04% | 4／5／7 |
| 仅调整扫描次序 scan | 3247.28 | 增加101.24秒，3.22% | 4／0／12 |
| 两种机制同时使用 both | 3243.40 | 增加97.36秒，3.09% | 4／0／12 |

扩大集64次运行全部完成清除，并通过独立计时、实际观测、覆盖证书和真实位置保留检查。普通均匀布局之外，还包含10源最小半径、边界集中和单侧集中布局。

首轮3个条件中 probe 平均省57.42秒，其中一个普通布局省186.80秒；另外一个条件慢14.54秒，一个完全相同。合并两批19个条件后，probe 平均只省10.18秒（0.33%，5快6同8慢），scan 平均慢113.19秒（3.62%）。报告扩大集和合并值，避免只展示最有利的首轮结果。

扩大集 probe 的平均移动少8.01秒，却增加了检测4.69秒、切换0.88秒、失败清除1.13秒，最终只省1.32秒。扫描前瞻虽然平均少约9.94次检测，但多走161.43秒，节约检测数并不等于缩短任务时间。

**处理：三个候选均不晋升主方案。** 开发收益已不足以支持替换，因此没有继续为它们运行独立性能留出集。本轮的压力检查用于验证合法反馈处理和完成证书，不能用其有利场景平均值弥补开发集的弱收益。

机器可读汇总见 [development-analysis-v1.json](results/development-analysis-v1.json)，两批独立原始汇总见 [首轮](results/development-v1/summary.json)和[扩大轮](results/development-expanded-v1/summary.json)。每次运行的源布局、实际动作、完整建模轨迹及独立检查保存在相应 `cases/` 中。

另外，9组标准压力布局和6组从开发轨迹构造的近原点反例，lean 与 probe 共30次运行全部通过。probe 在这些条件中实际产生7次无信号探测，完整任务仍能完成；相对 lean 为7快7同1慢，平均省93.96秒。这组刻意构造的压力条件不代表总体布局分布，其收益不并入开发性能均值。详见[压力结果](results/stress-v1/summary.json)及[全批次分开汇总](results/analysis-v1.json)。全轮共109次完整运行，无失败；另有8项行为测试。

## 具体改了什么

### 1. 将不保证接收的测点纳入候选

原局部策略只从能够证明继续收到信号的测点中选择。新候选允许在当前位置、短横向偏移或后续路线附近增加一次检测；无信号视为题目允许的正常反馈，继续收缩位置集合。

设源位置为 g，固定未知接收半径为 R。已有正测点集合为 W，负测点集合为 N。给定一个假想位置 g，其半径可行区间为：

```text
L(g) = max(1000, max_{w∈W} ||g-w||)
U(g) = min(1500, min_{n∈N} ||g-n||)
```

负测点给出严格上界，代码留有数值余量。先在位置可行多边形中生成8个确定性面积样本，剔除目标圆外、失败清除圆内和半径区间矛盾的样本。对每个剩余位置，采用该可行半径区间内均匀分布作为**行动评分的设计假设**。这不是官方分布，也不是由联合均匀先验严格推导出的后验。

在候选点 q，按距离落在上述区间内的比例估计收信权重；同时评价收到方向／近距和无信号两条分支。无信号分支使用最小接收半径的排除圆，并使用固定半径推导的正负测点半平面。未来两步只安排有接收证书的测向，之后加显式尾部成本代理。

评分由即时移动、检测和切换成本，加上情景延续成本的80%平均值与20%最大值组成。误差使用−1、0、+1度三个评分节点。该最大值仅覆盖有限设计样本，**不是连续可行域上的最坏情况保证**。

每个频道最多额外探测两次；只有估计比原动作至少省5秒才选用；已承诺的有限光学覆盖计划保持执行。真实动作完成后，仍由原有 FeedbackModel 根据实际回包更新证据，样本和预测从不写入完成证书。

### 2. 让扫描次序考虑可能发现的源

构造12个共同设计场景，每个场景包含假想源数、频道子集、位置和固定半径。源数设计分布为10至16的均匀分布，位置采用区域面积网格，半径使用1000、1250、1500米三个节点；实际负反馈会限制这些场景。

对已有覆盖任务逐一尝试“先执行哪个扫描点”。预测中，收到信号的频道退出未知频道扫描队列，无信号的频道继续完成覆盖，比较移动与检测成本。只改变下一扫描任务；真实反馈后重新规划。实际覆盖证书依旧来自已经执行的检测。

## 模型诊断

**探测方向有合理性，但当前评分没有充分评价后续总路程。** 首轮186.80秒的单场改善分解为少移动138.80秒、少检测40秒和少切换8秒。清除顺序相同；已知源检测由13次增至14次，未知频道搜索由102次减至93次。收益主要来自利用已有位置的观测改变接近路径和沿途覆盖，并不能解释成“定位检测减少”。扩大后，这些间接收益经常被后续绕行和额外清除尝试抵消。

首轮6个被选探测全部收到方向；扩大集中 probe 的19个探测为17次方向和2次无信号。因此，无信号处理确实在完整任务中运行过，但还没有将其单独做反事实拆分，不能把整场收益全归给这条分支。

**原接收证书没有被证明有错误。** 首轮每个选点都存在满足已有观测、却在该点无信号的合法源。即使某次 `design_signal_mass=1`，也只是有限面积样本全部收信，不能解释成100%真实接收概率。构造的反例把目标源放到原点同一真实方位10米处、半径1000米，仍保留原点首次读数，却在原探测点无信号。这是放宽决策约束后承担的信息风险，不是修复错误证书。

**扫描前瞻的主要问题是延续过程与真实策略不一致。** 它假设发现一批源后马上全部访问，再去下一个扫描点；真实 lean 会联合重排已知源与扫描点。首轮普通布局中，原点发现6个源后，真实程序仍先去下一个扫描点，而前瞻强制先服务6个分散源，系统性高估原点开局费用。

此外，预测发现后直接访问假想源的准确位置，遗漏了定位过程和已有观测对定位几何的作用。三组首轮候选都绕过原点先移动226.70秒；初始12场景仅7个支持改序，配对预测收益从−556.13到+687.55秒，变化很大。这是有限设计场景的离散度，不能当作抽样置信区间。

边界布局中，一次扫描被预测平均发现1.92个源，实际15个频道全部无信号。这说明均匀面积假设和简化服务过程对特定布局可能产生明显偏差。单纯增加场景数或调距离权重，无法修复这种结构失配。

## 对2300秒目标的判断

用户给出的对方成绩为第三问整局约2300秒，但源数、清除完成情况、布局及这是单局还是多局平均尚未知。它能提示继续检查模型，不能直接确定我们相差多少。

我们已有5次用户提供的官方演练平均整局3015.01秒。若仅作为目标算术对比，降到2300秒需减少23.72%；若其他费用保持不变，移动时间需要由2254.01降到约1539秒，即减少约31.72%。这是目标分解，不是已证明可实现的改进空间。

本轮0.04%的扩大集探测收益远不足以支撑该目标。下一次若继续研究，应先使前瞻中的定位与源／扫描调度接近真实求解流程，并检查预测改进是否在实际延续中兑现。已有联合调度、成本预测等历史候选也应作为对照，不能把它们重新命名后算作新的突破。
