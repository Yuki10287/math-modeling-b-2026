# 第四问第四批官方演练结果分析

本批为用户提供的《测试结果(4).zip》，包含01—04四组请求反馈和定位轨迹。结论是：旧版 shared 再次完整清除了全部源，但时间表现基本没有变化；以平均整局5000秒为目标，仍需约20.7%的实质改进。本批不是 share25 候选的官方验证。

## 1. 首先核清测试版本

四场日志中的 `variant` 均为 `shared`，每场11项运行源码指纹均与冻结旧版匹配。用户确认使用 `q4_official_client.py` 启动，正是已有主方案。上一轮推送新增了独立 share25 入口，保留了旧入口，因此沿用这个命令会继续运行 shared。

这意味着本批可增加主方案的可靠性与性能证据，但不能用于判断 share25 的官方提速效果。下一次验证候选应运行项目根目录的[运行第四问候选.cmd](../../../../运行第四问候选.cmd)，确认窗口及日志显示 `share25`；详细操作见[候选演练说明](../../05_候选share25/reports/第四问share25候选演练说明.md)。

## 3. 与约5000秒参考的差距

目前只有用户观察到的他队约5000秒，缺少其源数、清除比例、类型构成和多场记录，尚不能建立同条件排名。若对方同样是第四问、全清且多场平均约5000秒，其效率确实比本批更好。

把5000秒作为内部目标是合理的：当前平均需要减少1304.11秒，即20.69%。这不是几次检测或清除的小幅调整就能补齐的差距。share25此前约6.04%的改进仅来自本地配对条件，不能直接外推为本批官方收益；这个改进量级本身也不足以覆盖约21%的目标。

## 4. 时间主要花在哪里

逐条按题目计费重算：

\[
T=L/5+5N_{\rm 测量}+N_{\rm 切频}+5N_{\rm 清除成功}+3N_{\rm 清除失败}.
\]

| 费用项 | 四場合计（秒） | 占总时间 |
|---|---:|---:|
| 移动 | 17884.44 | 70.92% |
| 测量 | 5740.00 | 22.76% |
| 切频 | 1099.00 | 4.36% |
| 成功清除固定费 | 250.00 | 0.99% |
| 失败清除固定费 | 243.00 | 0.96% |

四场全部走完25个扫描站。按动作目的归类，扫描及其对应移动平均4555.57秒，占72.26%；该数字包含从清除点接到扫描点的移动，与上表的费用分类交叉，不能相加。

1148次测量中，1052次用于扫描；最终证明无源的30个频道共测了750次，占所有测量65.33%。这批数据进一步支持：固定全域覆盖和无源频道查漏是主要开销。

最后一次清除后的查漏尾段分别347.02、128.76、0、1606.89秒。第四场在4604.60秒已经清除最后一源，之后仍需证明无遗漏。但这些总源数由用户事后提供，求解器当时不知道，因此不能直接删除尾段。即使假设能免费知道全清、删去四场全部尾段，平均仍为5783.44秒，单独处理尾段也不足以达到5000。

第二场有40次失败清除，其中32次集中在频道15。该源光学覆盖计划包含108个点，实际局部动作耗时约530.48秒，值得检查长条定位区域的测量价值和搜索顺序。不过全部失败清除的固定费平均只有60.75秒/场；减少失败次数需要连同相关移动与获得信息的代价评价。

## 5. 固定结构为什么很难达到5000秒

对本批相同25个扫描站（包含起点）独立求最小生成树，长度为18005.67米。任何访问全部站点的连续路线都至少需要3601.13秒移动。

若继续保留这25站，以及每场实测的测量、切频和清除数量，再加上相应非移动费用，得到条件下界：

| 场次 | 固定站集及动作费用下界（秒） |
|---|---:|
| 01 | 5350.13 |
| 02 | 5641.13 |
| 03 | 5307.13 |
| 04 | 5438.13 |
| 平均 | 5434.13 |

因此，仅在当前动作次数下重排原25站，甚至理想化地消除额外定位绕路，也不能让这批均值达到5000秒。这是固定站集、固定动作费用下的下界，不是整个第四问的最优下界；新模型可以改变这两个条件。

优先研究方向应是覆盖证明与检测安排的联合优化：充分利用定位和服务过程中到达的测点，及时认证已经查清的区域，让后续扫描任务真正减少。此前22站实验仅缩短约114米固定路线，说明“减少站数”本身不足以证明整局提速。其次再处理个别长条定位区域的高代价光学搜索。

这类调整直接对应题目的观测约束和主要费用，是合理的建模改进。依据本次真实总数提前退出，或只对这四场的频道、布局调规则，则不能作为可推广模型。

## 6. 核查范围与下一步

四场不存在客户端错误、拒绝动作或重复的已接受请求。1279个动作逐项重算，与官方虚拟时间最大累计差约0.0000145秒。全部1080份三角形无源证据、36份完整光学覆盖计划和14份单点清除保证通过独立几何核查；实际成功响应与用户提供总数50/50吻合。

前三场的动作、定位轨迹与完成证书均严格离线复现。第四场前185个动作一致，第186个动作的下一扫描点出现分歧。补充诊断发现，在第186、197个动作，两种路线由同一组点的正反顺序构成，当前距离评分分别相差约1.82×10⁻¹²米和0米。仅对这两处等价评分沿用日志方向后，318个动作、轨迹和证书全部一致，见[回放补充诊断](../results/official_q4_20260912_batch4_replay_detail.json)。

上述有条件核查不算严格复现，也不能推断反向路线的最终整局时间相同。原始官方反馈、实测时间和几何证据仍可独立核查；路线评分近似并列时需要稳定选择规则，是此前发现的复现性问题。本次未修改冻结求解器，也没有把旧反馈接到不同位置的动作上估计新成绩。

材料没有真实源坐标、朝向、半径、官方结果表或加密行为日志，不能直接检查每一步定位区域是否包含真实位置，也不能核验他队排名。客户端墙钟耗时约5.47—7.08秒，与这里的数千秒虚拟时间是不同指标。

建议先使用正确入口补齐share25的官方验证，并保存官方总数、类型构成和两份客户端日志；若支持同一案例重复运行，优先做shared与share25配对。与此同时，在本地研究能够实际减少扫描和检测任务的覆盖模型。当前主方案具备较好的完整性证据，但不应据此认定效率已经足够优秀，也不宜承诺现候选已经能达到5000秒。

本次只做离线分析，没有启动或连接官方模拟器，没有修改求解策略。可复核材料：[分析程序](../code/analyze_official_archive.py)、[去身份化逐动作与汇总结果](../results/official_q4_20260912_batch4_analysis.json)。
