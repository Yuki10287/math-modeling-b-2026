# 第四问25站＋保序删点候选运行说明

这一入口使用原share25的25站覆盖、测向和任务调度，在光学执行阶段跳过可以严格证明必定失败的原探测点。日志版本为 `share25_prune`。每次完整运行会用实际接受的动作反馈，独立核对全部光学覆盖和删点证据，再记录会话总结。

## 队友如何运行

在完整仓库根目录打开终端，先更新代码：

```powershell
git pull --ff-only
```

由操作人手动启动官方问题4演练并等待接口就绪，然后执行：

```powershell
python -X utf8 src/q4_model/q4_share25_prune_client.py --robot-id 202619002152 --log q4-share25-prune-practice-01.jsonl
```

如果终端已经位于 `src/q4_model`，则使用：

```powershell
python -X utf8 q4_share25_prune_client.py --robot-id 202619002152 --log q4-share25-prune-practice-01.jsonl
```

队号必须与模拟器中登录的队伍一致。每场换一个新日志编号，例如02、03；日志与证据文件都不会覆盖已有文件。默认地址是 `http://127.0.0.1:2026`，只有模拟器确实使用其他端口时才追加 `--url http://127.0.0.1:端口`。

保留完整仓库：新客户端与运行模块位于 `src/q4_model`，共用几何和通信模块位于相邻 `src/q3_model_v2`。运行时不需要进入研究脚本目录，也不需要手动设置 `PYTHONPATH`。原来的 `q4_share25_client.py` 及“运行第四问候选.cmd”仍选择原share25；要运行本次删点版本，请使用上面的新文件名。

原环境若已经能运行share25，所需第三方依赖没有增加。新环境使用Python 3.11或更高版本，并安装已有依赖：

```powershell
python -m pip install -r src/q4_model/02_主方案25站_shared/code/requirements.txt
```

只查看参数不会连接模拟器：

```powershell
python -X utf8 src/q4_model/q4_share25_prune_client.py --help
```

需要核对拿到的代码是否与已验证版本一致时，在仓库根目录执行以下只读检查；它核对15个运行文件和发布验证记录，也不会连接模拟器：

```powershell
python -X utf8 src/q4_model/05_候选share25/code/verify_share25_prune_release.py
```

发布指纹见[候选发布记录](../results/share25_prune_client_release.json)，本地接入结果见[客户端验证报告](25站保序删点客户端接入验证.md)。

## 每场保留哪些记录

运行命令会生成两份文件，路径以当前终端目录为准：

- `q4-share25-prune-practice-01.jsonl`：请求、响应、实际计时、版本及源码哈希。
- `q4-share25-prune-practice-01.jsonl.beliefs.json`：位置区域、原光学计划、删点证明和执行轨迹。

另记录官方结果页的总源数、全向/定向数量、清除数、总虚拟时间和程序运行时间。程序不能事先获得官方真实总源数；终止仍依靠16源上限或25站连续无源证书。

结束时应看到“完整清除证书：通过”“保序删点核验：通过”“退出请求：已接受”。输出中的“成功之前已跳过的必失败点”只统计原首次成功位置之前的删除点，成功后本来就不会访问的计划点不计入它。部分合法场景该值为0，表示没有可证明提前省掉的点。

如果异常中止，保留上述两份日志和终端错误内容。请求重试、退出与日志保护沿用原通信模块；失败或不完整会话不会显示为成功完成。

## 模型效果与边界

冻结的独立本地实跑验证了该模型与原研究候选的动作等价；同批轨迹的受限重算显示约1%的平均节时，用户四场旧官方日志的受限重算约2.7%。这是原有记录上的证明与计费结果，不是这份新客户端已取得的官方成绩。

保序删点对同一合法静态场景保持原首次成功点及后续决策状态，并且虚拟费用不增加；额外的证明计算属于墙钟时间，两种时间分别记录。新22站组合不包含在本入口中，相关速度与压力风险见[整体研究汇总](整体模型继续改进实验汇总.md)。
