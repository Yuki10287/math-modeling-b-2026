# 25站保序删点客户端接入验证

本次按用户审核的范围，只在 `src` 内新增候选运行模块、验证程序、记录与导航；原shared、share25入口和旧实验冻结源码保持不变。新的运行命令见[候选运行说明](25站保序删点候选运行说明.md)。所有实际客户端验证都由测试程序创建自己的127.0.0.1随机端口服务，显式排除官方默认2026端口，没有连接官方模拟器。

## 运行实现

新 `q4_share25_prune_client.py` 选择 `ordered_optical_prune.solve_multi(..., variant='share25')`，外部日志使用独立标识 `share25_prune`。负反馈位置证明由 `negative_region.py` 提供。模型函数体与冻结研究候选等价，生产代码不在运行时修改旧模块或动态注入求解器。

客户端复用旧通信、重试、计费状态与25站终止检查。新子类只额外记录通信层已接受的动作，作为独立的事实账本。完整求解结束后，`prune_proof.py` 与 `negative_region_proof.py` 检查全部原光学覆盖、收缩与删点证明、执行顺序、成功前缀和真实既往反馈；异常时保留原始错误、请求日志和证明轨迹。审计条件使用显式异常，Python优化模式不会关闭它们。

## 验证结果

| 检查 | 结果 |
|---|---|
| 9项协议与异常测试 | 全通过：选择新求解器、账本来源、重试只执行一次、清除不切频、失败与中断退出、日志保护、伪完成拒绝及源码变化检查 |
| 实际CLI：48000普通布局 | 10/10全清，6622.715332秒，成功前实际跳过20个必失败点，使用连续无源证书 |
| 实际CLI：53300极端误差布局 | 16/16全清，3789.927298秒，本场删点为0，使用16源上限证书 |
| 两场CLI对比直接生产模型 | 动作与结果精确一致；证明轨迹仅排除计算耗时字段后精确一致；计费及独立连续几何核查通过 |
| 两场首个测量响应断开 | 以同一请求编号和相同字节重试，服务端只执行、计费一次 |
| 命令行与导入 | 仓库根目录相对入口、其他目录绝对入口、无PYTHONPATH均通过；import/help在禁止联网的检查下通过 |
| 最小运行闭包 | 只复制15个登记文件，无研究目录，全部运行模块导入、指纹核对和help通过 |
| 独立证明器 | 正常及优化模式各核对22个函数的逻辑等价、25份既有候选轨迹的187份光学计划；8项伪证书与3项账本篡改均拒绝 |
| 原方案冻结检查 | 55个旧运行与证据文件保持一致 |

上述两场属于客户端接入回归，使用已有布局，不能计为新独立性能样本或官方演练成绩。原研究的平均节时与风险继续按[整体实验报告](整体模型继续改进实验汇总.md)解释。
