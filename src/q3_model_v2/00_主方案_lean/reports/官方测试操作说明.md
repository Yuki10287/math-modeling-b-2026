# 第三问模型改进版：官方模拟器操作说明

本入口调用已冻结的 `lean` 模型，程序只支持**问题3（全向源）**。原冻结版本有12项本地HTTP替身检查，另已核验用户提供的5次该版本官方演练日志，见[演练结果复盘](../../05_官方演练复盘/reports/官方演练五次结果分析与下一步.md)。目录调整后的实际CLI另设[本地回归](../../tests/test_direct_entry.py)，历史检查与 `--help` 不能代替该回归。助手只运行本地检查，官方演练和正式测试由队员手动操作；现有演练不等同于正式测试交付记录。

## 推荐操作

1. 使用完整项目，不能只取一个阶段文件夹或启动文件。可先在项目根目录执行 `python -X utf8 tools/run_study.py verify`，核对是否仍为已冻结主版本；此项只读文件，不连接模拟器。
2. 打开官方模拟器并登录。先不要点击开始。双击项目根目录的[运行第三问.cmd](../../../../运行第三问.cmd)，它会先检查Python环境并校验版本；检查阶段不会连接模拟器。
3. 按窗口提示填写参赛队号，必须与模拟器当前登录账号完全相同，不是队员姓名或手机号。端口未改过就直接按回车，采用2026。
4. 回到模拟器，选择 **问题3演练测试**，启动并等待5秒倒计时完全结束。此时接口才开放。
5. 回到启动窗口，按回车开始执行。本程序会依次发送进入、检测、清除和退出请求，不需要手动逐条操作。
6. 程序结束后检查窗口中的“完整清除证书：通过”“退出请求：已接受”，并核对模拟器的结束提示。演练界面可显示干扰源总数，检查它是否与程序成功清除数相等。

按照提供的附件1，演练不限次数，问题3正式测试有3次机会，成功启动正式测试就占用一次。现有五次演练对应lean版本；若更换电脑、运行环境或程序版本，应先核对环境及版本。要进行正式测试时，运行方法不变，由你在模拟器选择“问题3正式测试”；程序本身没有演练/正式切换参数，也不能识别你选择了哪种模块，因此务必确认是问题3。

## 直接从命令行启动

[official_client.py](../../official_client.py)与8个求解模块、共用几何模块集中在 `src/q3_model_v2/`，直接启动时不依赖 `tools/` 组装的临时目录。保留完整仓库并准备好环境后，先由队员手动启动问题3，等待5秒倒计时结束、接口就绪，再在仓库根目录执行：

```powershell
python -X utf8 src/q3_model_v2/official_client.py --robot-id YOUR_TEAM_ID --log NEW_LOG.jsonl
```

- 将 `YOUR_TEAM_ID` 替换为当前模拟器登录队号，`NEW_LOG.jsonl` 换成这次尚不存在的文件名。程序拒绝覆盖旧日志。
- 日志路径相对于执行命令时的工作目录；若指定子目录，应先创建其父目录。可使用绝对路径保存到指定位置。
- 默认地址是 `http://127.0.0.1:2026`。若队员已在模拟器修改端口，在命令末尾添加 `--url http://127.0.0.1:实际端口`。
- 从其他工作目录启动时，使用客户端文件的完整路径，并用引号包住含空格的路径。模块导入以客户端所在目录为准。
- 此命令会直接进入接口执行流程，没有CMD中的等待确认步骤。只读参数可运行 `python -X utf8 src/q3_model_v2/official_client.py --help`，但帮助显示成功不能证明完整求解和日志收尾正常。

仅做本地入口检查时，从仓库根目录运行下列命令；测试使用本地替身，不连接官方模拟器：

```powershell
python -X utf8 -m unittest discover -s src/q3_model_v2/tests -v
```

## 日志在哪里

根目录CMD会在 `local_data/official_runs/q3/` 中自动生成两个不覆盖旧文件的记录：

- `q3-时间-随机编号.jsonl`：请求、反馈、异常和最终汇总。
- 同名的 `.jsonl.beliefs.json`：位置候选区域和调度轨迹。

直接CLI则保存 `--log` 指定的JSONL和同名 `.jsonl.beliefs.json`，不自动把相对日志路径改到上述目录。

请保留这两个文件和模拟器测试案例编码、结果汇总。正式测试还需要按题目要求从**模拟器日志列表导出官方加密行为日志**；本程序JSONL不是那份正式日志。

## 整理后的入口

正式运行模块集中在第三问顶层；直接CLI可独立加载这些模块。项目根目录CMD仍保留准备依赖、核验冻结版本和自动命名日志的流程；组内历史CMD/PS1保留作溯源。实验仍通过 `tools/run_study.py` 按映射运行，不要在reports或code目录直接运行旧命令。

## 常见情况

- **运行环境检查失败**：当前启动工具需要Python 3.11或更新版本，以及NumPy、SciPy；先准备环境，再启动模拟器测试。已准备好Python时可在项目根目录执行 `python -m pip install -r src/q4_model/02_主方案25站_shared/code/requirements.txt` 安装项目共用依赖，路径位于第四问目录，但其中依赖也用于当前统一启动工具。
- **连不上**：检查5秒倒计时是否已结束、测试是否仍在进行、端口是否一致，以及程序与模拟器是否在同一台电脑。
- **accepted=false**：常见原因是参赛队号不一致、局面状态不允许动作，或对同一局重复进入；保留日志核查。
- **no_target_in_range**：部分失败清除属于模型计划中的光学尝试，不能单凭这一条认定程序出错；最终以成功清除数和完整证书为准。
- **异常退出或测试已结束**：接口会关闭。保留日志和界面提示，不要向同一已结束测试重复启动；新的运行需要新的一局。

运行官方模拟器需要按附件要求保持联网。测试中每次检测的5秒属于虚拟时间，程序无需现实等待5秒。客户端按实际剩余现实预算执行，丢失响应时仅重试相同请求ID与相同内容，避免重复收费。
