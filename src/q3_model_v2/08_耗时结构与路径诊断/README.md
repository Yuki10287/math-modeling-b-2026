# 第三问：耗时结构与路径诊断

**当前结论：原有任务顺序和最后查漏的局部修补，都不足以支持大幅降时；“先扫描后清除”的新结构对照反而慢24.13%。** 本阶段先核验用户提供的五次官方演练，再作两类离线诊断，并在新自建布局中检验覆盖优先模型。正式入口继续使用time/lean；所有新计算均在本地进行，没有连接官方模拟器。

## 1. 先区分大额费用与可省费用

从原始反馈和规划记录重新构造35个扫描任务、63个源服务任务，98个任务块包含全部671个已接受动作。各任务的入口指第一个实际动作点，不是真源位置；前往该点可能同时承担定位选点的作用。

| 互斥费用 | 平均每局虚拟秒 | 占整局 |
|---|---:|---:|
| 前往扫描点的移动 | 857.14 | 28.43% |
| 前往各源首次主动服务点的移动 | 992.21 | 32.91% |
| 源服务内部的后续移动 | 404.65 | 13.42% |
| 检测、切频及清除固定费用 | 761.00 | 25.24% |
| 合计 | **3015.01** | **100%** |

跨任务进入移动占61.34%，是最大的费用块，但不能因此声称它都是浪费。63个源中，31个开始主动服务后不再测向，26个测一次、6个测两次。主动定位测量与切频平均仅43.60秒；失败清除固定费25.20秒；全局全部切频费106.80秒。只压缩这些小项，无法解释从3015秒到2300秒约715秒的差距。

每次源服务的实际折线与其固定事后起终点的直线相比，额外路程合计平均仅80.20秒。直线可能缺少必要测向，这个差额也不能直接兑现。详见[完整互斥费用说明](results/official_time_audit_notes_v1.md)与[逐任务核验](results/official_time_audit_v1.json)。

## 2. 事后知道全部测点，重排任务能省多少

每个已执行任务作为一个块，保留块内全部动作、坐标与顺序。块的起点、终点和内部费用已知，块间按欧氏距离除以5计费。接收机频道也进入状态：检测可能切频，清除不改变接收机频道。以“已完成的块集合、最后一个块、当前频道”为状态进行精确动态规划，优化完整开放路线，不要求返回原点。

比较两种约束：

- **保持各频道原顺序**：同一频道的检测与清除仍按原顺序发生，只允许其他任务交错。
- **仅保持清除前后状态**：允许同一频道在清除前的检测换序，但每个动作仍位于该源成功清除的原来一侧。第三问固定源、固定接收半径及固定地点误差，使相同频道、坐标和清除状态下的物理反馈保持一致。

| 演练 | 原整局秒数 | 保持频道顺序最多省 | 放松为清除状态约束最多省 |
|---|---:|---:|---:|
| 01 | 3148.45 | 3.49 | 3.49 |
| 02 | 3026.76 | 0.00 | 0.00 |
| 03 | 3013.32 | 0.00 | 0.00 |
| 05 | 2846.74 | 0.00 | 0.00 |
| 07 | 3039.79 | 0.00 | 65.22 |
| 平均 | **3015.01** | **0.70** | **13.74** |

全部五例求得上述约束下的精确最优值，未触及状态数上限。放松版本平均降至3001.27秒，改善约0.46%。计算后又逐动作独立核算费用，并检查每个动作的清除状态。

**这不是一个在线程序，也不是原题最优时间的下界。** 事后知道的未来测点不能交给在线求解器。这里的上限仅约束“保留这些完整任务块和实际动作点，再重新排序”的改进；改变观测点、拆分任务、增加共享测向或改变块内动作，都在此范围之外。全清证书依据仍是原有真实反馈集合，没有创造其他坐标的反馈。

完整结果：[保持频道顺序](results/block_route_diagnostic_v2.json)、[放松顺序](results/block_route_relaxed_v2.json)。v1是澄清两种约束说明前的开发记录；v2只更新说明及相应源码指纹，算法与数值结论相同。

## 3. 在已走过的路上加测，能免去尾段吗

此前只检查停靠位置，本轮将最后清除之前走过的整条折线都算作潜在测点，并允许沿线任意加测。这是比真实执行更乐观的几何能力检查，尚未把新增测量当作已获得证据。

03、05、07三局仍各自存在圆域内的点，到此前整条路径的距离大于1000米。一个接收半径为1000米的未知源仍可能位于该处；沿原路线任意加测都无法排除它。三局成功清除数均小于16，不能仅凭数量上界结束。

进一步，设最后清除点为s，这样的未排除点为z。任何后续可靠检查路线至少要进入以z为圆心、1000米为半径的圆，因此移动长度至少为 `max(0, ||s-z||−1000)`。它给出保留此前路线时的必要移动费用，并非可达到的完整最短路线。

| 演练 | 原尾段全部费用 | 其中移动费 | 后续必要移动至少 | 尾段移动最多可省 |
|---|---:|---:|---:|---:|
| 03 | 194.09 | 76.09 | 56.39 | 19.71 |
| 05 | 253.03 | 134.03 | 104.19 | 29.84 |
| 07 | 286.97 | 244.97 | 238.44 | 6.53 |

最后一列仅是移动节省的乐观上界，未扣新增检测费用，不能当作整段总费用的改善上界。它要求此前路线和最后清除点不变；改变更早的路线或清除顺序后不能套用。

例如07的点(1570,−870)距此前折线最近仍为1010.67米。从最后清除点出发，即使直接前往能够检测该点的位置，也至少移动1192.20米、耗238.44秒。这说明该局看似可惜的244.97秒尾段移动，在此前路径固定后已经接近必要费用。

详见[折线覆盖及下界证据](results/corridor-audit-v1.json)。圆域内严格大于1000米的点用于证明物理缺口；整格覆盖另用充分条件核验，不用“网格上没发现缺口”冒充连续覆盖证明。

## 4. 改变结构：先覆盖再集中服务的本地对照

为避免仅在固定任务块内找改进，增加了一个明确的结构实验：存在未知频道时优先选择覆盖扫描，沿扫描停点保留原有共享测向；完成未知频道覆盖或发现数达到16后，再主动移动服务已知源。扫描停点能够立即保证清除的源仍就地清除，整个流程继续使用原反馈模型、原局部定位器与原完成证书。

`survey` 使用原顺手机会规则。`survey_all` 还尝试对所有未在该点测过、尚不能可靠一次清除、无冲突且可以保证接收的已知源补充测向。不根据真实位置决定补测，也不把预期接收当作实际反馈。

看结果前固定四类新布局：均匀、稀疏、边界和单侧各一个，分别使用smooth、extreme误差场，共8个配对条件、24次完整运行。四个抽样布局恰好都为10源，因此结论尤其不能外推到全部10至16源布局。两个候选达到平均省2%、更快条件多于更慢条件且全部审计通过，才考虑进一步留出测试；本轮不按单局表现修改参数。

| 指标 | lean | survey | survey_all |
|---|---:|---:|---:|
| 平均整局虚拟秒 | **3046.94** | 3782.07 | 3782.07 |
| 相对lean增加 | — | **24.13%** | **24.13%** |
| 平均移动秒 | 2276.82 | 3056.95 | 3056.95 |
| 平均测量次数 | 116.25 | 111.50 | 111.50 |
| 最后清除后的平均尾段秒 | 480.41 | 0.00 | 0.00 |
| 更快／相同／更慢 | — | 0／0／8 | 0／0／8 |

两种候选多用移动780.13秒，虽然其他动作合计少45秒，整局仍增加735.13秒。最差条件增加1317.99秒。**尾段变成零只表示把覆盖安排在最后清除之前，并不意味着节省了总费用。** 这也反证了以尾段长度替代原题总时间目标的做法。

在这8个条件中，`survey_all` 没有出现原规则之外的额外合格补测，两候选动作逐条相同。这不是两个独立的模型收益证据，也不能推出所有更密集的多源观测都没有价值；目前保证接收的候选范围没有提供额外机会。

24次完整开发运行全部通过独立计时、观测、完成证书、真实位置保留与选择行为检查，18份依赖源码指纹保持一致。另有2个布局、4次完整前置运行，验证复制的参考流程与lean逐动作相同；补测的5类跳过条件及同站不重复规则也通过检查。这些次数不是独立布局数。

该候选未通过开发收益门槛，不进入留出测试，不加入官方入口。见[预定方案及源码指纹](results/survey-development-v1/manifest.json)、[完整开发结果](results/survey-development-v1/summary.json)和[前置检查](results/survey-development-v1/preflight.json)。

## 5. 对下一步模型的约束

现有主方案没有出现明显的大量无效失败或可随意删除的尾段。若追求较大收益，应研究更早的观测布置，让同一条路径同时完成未知频道覆盖和多个已知源的定位，随后选择清除时机。只给已有任务重新排序，不能改变定位时形成的路线。

本轮否定了直接把覆盖和清除先后分开的简单实现。若继续研究，应让观测位置、共享测向与清除时机共同生成，评价整条路线的费用；这仍是待验证的方向，不能由现有诊断宣称必然更好。不能把未来源位置、事后最佳路线或其他测点的假造反馈放入在线评分，也不能为了接近2300秒而删去不存在证明。对方演练的源数、布局、完成证据尚不清楚，2300秒目前只是用户提供的参考值，不是已确认可比的目标成绩。
