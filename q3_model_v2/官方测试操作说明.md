# 第三问模型改进版：官方模拟器操作说明

本入口调用已冻结的 `lean` 模型，程序只支持**问题3（全向源）**。接口已通过12项本地HTTP替身检查，另已核验用户提供的5次该版本官方演练日志，见[演练结果复盘](官方演练五次结果分析与下一步.md)。本次整理未连接官方模拟器，现有演练也不等同于正式测试交付记录。

## 推荐操作

1. 使用本机完整的 `q3_model_v2` 文件夹，或从GitHub获取已同步的完整项目。不能只取一个启动文件。可先在本目录执行 `python -X utf8 verify_main_solution.py`，核对是否仍为已冻结主版本；此项只读文件，不连接模拟器。
2. 打开官方模拟器并登录。先不要点击开始。双击本目录的 **运行第三问.cmd**，它会先检查Python和NumPy；检查阶段不会连接模拟器。
3. 按窗口提示填写参赛队号，必须与模拟器当前登录账号完全相同，不是队员姓名或手机号。端口未改过就直接按回车，采用2026。
4. 回到模拟器，选择 **问题3演练测试**，启动并等待5秒倒计时完全结束。此时接口才开放。
5. 回到启动窗口，按回车开始执行。本程序会依次发送进入、检测、清除和退出请求，不需要手动逐条操作。
6. 程序结束后检查窗口中的“完整清除证书：通过”“退出请求：已接受”，并核对模拟器的结束提示。演练界面可显示干扰源总数，检查它是否与程序成功清除数相等。

按照提供的附件1，演练不限次数，问题3正式测试有3次机会，成功启动正式测试就占用一次。现有五次演练对应lean版本；若更换电脑、运行环境或程序版本，应先核对环境及版本。要进行正式测试时，运行方法不变，由你在模拟器选择“问题3正式测试”；程序本身没有演练/正式切换参数，也不能识别你选择了哪种模块，因此务必确认是问题3。

## 日志在哪里

本目录 `official_runs` 中会自动生成两个不覆盖旧文件的记录：

- `q3-v2-时间-随机编号.jsonl`：请求、反馈、异常和最终汇总。
- 同名的 `.jsonl.beliefs.json`：位置候选区域和调度轨迹。

请保留这两个文件和模拟器测试案例编码、结果汇总。正式测试还需要按题目要求从**模拟器日志列表导出官方加密行为日志**；本程序JSONL不是那份正式日志。

## 也可以手动运行

在本目录终端中，等模拟器倒计时结束后执行：

```powershell
python -X utf8 official_client.py --robot-id "你的参赛队号" --log "practice-v2-01.jsonl"
```

每局更换日志名；已存在的日志不会被覆盖。若端口改为2027，则增加 `--url http://127.0.0.1:2027`。双击入口已经自动选择本机可用的Python并生成新日志名。

## 常见情况

- **运行环境检查失败**：先解决Python与NumPy环境，再启动模拟器测试。已准备好Python时可用 `python -m pip install -r requirements.txt` 安装本目录要求的NumPy。
- **连不上**：检查5秒倒计时是否已结束、测试是否仍在进行、端口是否一致，以及程序与模拟器是否在同一台电脑。
- **accepted=false**：常见原因是参赛队号不一致、局面状态不允许动作，或对同一局重复进入；保留日志核查。
- **no_target_in_range**：部分失败清除属于模型计划中的光学尝试，不能单凭这一条认定程序出错；最终以成功清除数和完整证书为准。
- **异常退出或测试已结束**：接口会关闭。保留日志和界面提示，不要向同一已结束测试重复启动；新的运行需要新的一局。

运行官方模拟器需要按附件要求保持联网。测试中每次检测的5秒属于虚拟时间，程序无需现实等待5秒。客户端按实际剩余现实预算执行，丢失响应时仅重试相同请求ID与相同内容，避免重复收费。

依据：本地题目附件1第4.3—4.6节、附件2接口与计时规则。正式测试需要保留的字段与文件见[证据索引与交付清单](../论文整理/证据索引与交付清单.md)。
