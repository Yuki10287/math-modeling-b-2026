# 按版本和实验整理目录

这轮在原先按题目分组的基础上，继续把内部文件分为17个阶段：第一、二问3组，第三问8组，第四问6组。每组代码、结果、图表和报告一起存放，入口见[阶段导航](../src/README.md)。

## 具体变化

- 第一、二问区分共享几何核、早期预设测点、当前自适应求解，第二问专项验证归入当前求解组。
- 第三问区分lean主方案、局部选点、联合调度、成本预测、全局动作价值、官方复盘、正负反馈与扫描前瞻、闭环预测。原experiments下的两个探索分支也迁入相应组。
- 第四问区分公共几何、初版31站、25站shared基线、官方复盘与时间诊断、22站覆盖实验、share25候选及share25_prune最终方案。候选的模型、接口、压力结果和操作说明归在一起。

迁移覆盖2616个已有文件。求解源码与实验数据按原字节移动；Markdown链接和操作说明按新位置更新。模型参数、已选方案与实验结论不因目录整理改变。

跨题目的论文稿、总体方案与证据索引仍放docs。旧完整版本放archive。原题附件、个人日志、旧包和缓存不作为当前源码混放。

## 为什么使用统一运行入口

原代码存在同目录导入、跨问共享模块、依赖文件位置的输出路径，以及已冻结的源码指纹。现在阅读和编辑使用实际阶段目录；执行时工具在tmp中生成独立副本，恢复原相对路径，再执行原脚本。

这让原源码与历史指纹保持可核对，同时把代码和相关研究过程实际归组。不是把新的副本当成另一份维护代码。只编辑阶段目录里的code，使用项目根目录CMD或 [本地运行工具](../tools/README.md)。

三个根目录启动入口分别对应第三问time/lean、第四问shared、第四问share25候选。原来的启动文件保存在对应code中作历史记录；其中legacy_project_entry保存原根目录入口。发布校验在组装后的原路径上读取这些原文件；新根入口另做静态检查。

## 旧路径与原始证据

[studies.json](../src/studies.json)逐文件记录旧逻辑路径、新实际路径、所属阶段及迁移前SHA256。历史JSON中的机器路径、结果路径和源码哈希保持原始内容，不批量改写历史证据。人工查看时从各组README进入。

原始结果只移动、不重算。运行工具对默认生成的结果另存新批次；本轮检查均在本地进行，未连接官方模拟器。

## 验证

在项目根目录执行 `python -X utf8 tools/check_structure.py`，核对17组目录、三个入口、冻结证据与文档链接。实际运行与迁移字节核验记录见[本轮验证记录](study_reorganization_validation.json)。[上一轮顶层整理记录](reorganization_validation.json)作为历史保留。
