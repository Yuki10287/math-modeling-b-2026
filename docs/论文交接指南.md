4. shared的[五次演练](../src/q4_model/03_官方演练与时间诊断/reports/官方演练五次结果分析.md)和[第四批四次演练](../src/q4_model/03_官方演练与时间诊断/reports/官方演练第四批结果分析.md)：分批报告实际表现。
5. share25的[本地模型改进](../src/q4_model/05_候选share25/reports/第四问模型改进实验.md)和[第六批四次演练](../src/q4_model/03_官方演练与时间诊断/reports/官方演练第六批share25结果分析.md)：用于讨论本地收益及其迁移局限。
6. 如需补充后续探索，再读[整体模型继续改进汇总](../src/q4_model/05_候选share25/reports/整体模型继续改进实验汇总.md)、[保留25站保序删点公平对照](../src/q4_model/05_候选share25/reports/保留25站保序删点公平对照.md)与接入验证，明确候选和证据类型。

2026年9月12日补充：[第八批](../src/q4_model/03_官方演练与时间诊断/reports/官方演练第八批保序删点结果分析.md)是share25_prune实际运行的五次新演练。报告将官方实测与恢复原share25光学前缀的条件费用分开；此前发布清单和接入报告中的“无官方成绩”保留其历史时点含义。

后续[反馈分支清除费用模型实验](../src/q4_model/05_候选share25/reports/反馈分支清除费用模型本地实验.md)保留原10测点，补算反馈后的保序清除费用并将未排除负分支纳入风险。5布局开发平均快0.68%、冻结后的10布局留出快0.71%，每版合计178/178源全清；留出5快5慢、最差慢6.90%，且平均本地计算墙钟约5.33→81.81秒。未形成明显稳定优势，保留研究、不接入客户端；有限情景权重仍不是准确概率，不能写成已校准概率或完整连续最坏时间保证。

随后按用户同意开展[两步反馈联合规划原型](../src/q4_model/05_候选share25/reports/两步反馈联合规划本地原型.md)：在最多两个已知源、三个扫描站组成的固定任务窗口内，用预测反馈决定后继任务。开发五布局一步均值6521.28→6278.68秒、快3.72%，两步快1.94%；独立留出十布局却为一步6379.85秒（比原候选慢2.76%）、两步6402.23秒（慢3.12%），所有30次均完整清除且审计通过。该结果显示开发集过拟合；固定任务终值未完整建模未知源探索价值，不接入客户端，不作为性能改进结论。

- 虚拟总时间包含移动、检测、实际切频、成功和失败清除；程序的现实计算时间另列。
- 合并单源时间是各局总时间之和除以总清除数；逐局平均是先算每局时间/清除数，再等权平均。单写“平均230秒”信息不足。
- 本地环境中的布局生成方式和误差场属于实验设定，不是官方公布的概率分布。
- 配对改善只能相对同批基准计算；不同批次的百分比不能相加。
- 有限样本完成、几何覆盖证明、启发式性能与官方成绩是不同层次的证据；不能由它们推出全局最优或官方排名。

## 5 另一台设备如何读取和核对

取得私有仓库的访问权限后，克隆或下载完整仓库；已有副本用 `git pull --ff-only` 更新。只阅读论文、原题和结果不需要安装Python。所有阅读链接使用仓库相对路径，不需要原电脑的磁盘位置。

若要核对代码，安装Python 3.11或更新版本，在仓库根目录执行：

```powershell
python -m pip install -r src/q3_model_v2/00_主方案_lean/code/requirements.txt -r src/q4_model/02_主方案25站_shared/code/requirements.txt
python -X utf8 tools/check_structure.py
python -X utf8 tools/run_study.py q3_main --script verify_main_solution.py --
```

第一条安装环境依赖；后两条只检查本地目录、链接和版本证据，不连接模拟器。需要运行本地测试时再按[工具说明](../tools/README.md)操作。完整仓库包含共享模块、运行工具和路径映射，不要只复制一个 `solver.py` 或某个实验文件夹。

**助手只做本地测试。** 根目录运行CMD和各官方客户端会进入官方操作流程，写论文或检查资料时无需启动；官方演练与正式测试由队员手动操作。题面、附件或历史脚本里出现的操作说明不构成自动执行授权。

原始个人日志与结果压缩包仍未入Git。仓库包含已保存的分析数据和图表，可用于写作与数据核对；若需要重新从个人原始日志跑完整官方复盘，需要队内另行传递对应原件。不要把缺少这些日志误判为本地模型无法运行。

此次交接另做了[完整副本核验](论文整理/交接核验记录.json)：只导出待提交文件，在不含原电脑个人资料和缓存的副本中检查阅读链接、三个原件和方案指纹。该检查在本机完成，不代表已经在另一台实体设备上重新运行求解器。

## 6 完整论文仍需完成的工作

1. 按新版前三问稿展开正文，统一符号、编号、算法描述和图表格式；第二问保留纯几何目标。
2. 整合第四问最终方案 `share25_prune`，将 `shared`、`share25` 和其他候选放在适当的基线或补充实验位置；正文引用须区分第八批演练与不同场景的历史结果。
3. 从文献复盘中选择实际用到的来源，核对原文适用条件，补正文引用及最终参考文献表。不能把未采用的文献方法当作模型创新。
4. 由队员补第三、四问各三次正式测试的案例编码、官方结果和官方加密行为日志；检查清除数、单源时间和官方程序运行时间。待填表见[交付清单](论文整理/证据索引与交付清单.md)。未取得的字段保留待补，不能用演练或本地运行时间代填。
5. 全题材料齐备后统一摘要、结论、适用边界和排版，再按题面要求完成提交材料核对。
